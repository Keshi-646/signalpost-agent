# Signalpost Agent — Norwegian Company Information

A beginner-friendly Python project for the Signalpost hackathon. It looks up Norwegian legal entities by organization number using the official Brønnøysund Register Centre public API, normalizes company facts, attaches source evidence, stores snapshots in SQLite, reports field changes, exports JSON, and offers a Streamlit web interface.

## Important honesty note

The project **does not ship with 1,000 fabricated profiles**. You must run the collector against the live public registry and verify that at least 1,000 records were actually collected. The challenge evaluator may use its own 100 random companies, so the individual lookup endpoint and correctness matter as much as the seed dataset.

## Requirements

- Python 3.11 or newer recommended
- Internet access to `data.brreg.no`
- Windows, macOS, or Linux

## Setup in VS Code (Windows PowerShell)

Open this folder in VS Code, then open Terminal → New Terminal and run:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, use Command Prompt terminal and run:

```bat
.venv\Scripts\activate.bat
```

## Run the web interface

```powershell
python -m streamlit run app.py
```

Streamlit prints a local URL, normally `http://localhost:8501`. Open it in your browser.

## Run the agent from the terminal

Look up one company (replace the example with a valid nine-digit Norwegian organization number):

```powershell
python main.py lookup 923609016
```

Collect up to 1,000 real profiles from the official API:

```powershell
python main.py collect --target 1000
```

Export saved profiles to JSON:

```powershell
python main.py export --output profiles.json
```

The collector saves to `signalpost.db`. It may take time and can stop early if the public API is unavailable; inspect the output and database count rather than assuming it reached 1,000. A partial run can be followed by another run, but the printed `saved_this_run` is not the same as total unique profiles. The database primary key prevents duplicate organization numbers; check the database count before claiming coverage.

## Data and evidence design

Each profile contains the organization number, name, organization form, status, address, industry code and description, website, employee count, VAT registration flag, dates, latest submitted accounts year where available, retrieval timestamp, official source URL, and per-field evidence metadata. A field that is absent in the registry stays null. Each lookup is saved as a snapshot; later lookups produce a field-level change list.

Source: [Official English API documentation](https://data.brreg.no/enhetsregisteret/api/dokumentasjon/en/index.html). The registry API documents single-company lookup, paginated search, downloadable datasets, and update endpoints. Data is offered under the Norwegian Licence for Open Government Data (NLOD) as described by the registry.

## Architecture

```text
Company number / collector
        ↓
Input validation (9 digits + checksum)
        ↓
Official Brønnøysund API
        ↓
Identity guard (requested number must equal returned number)
        ↓
Normalization + source URL + retrieval timestamp + field evidence
        ↓
SQLite profiles + immutable history snapshots
        ↓
JSON export / Streamlit web interface / change report
```

## Model/API details and costs

- **LLM:** None required in this baseline. Facts are copied and normalized from source data rather than generated by a language model.
- **External API:** Brønnøysund Register Centre open-data API (`https://data.brreg.no/enhetsregisteret/api`).
- **API key:** Not configured or expected for the public entity lookup endpoints used here; verify the current official documentation before submission.
- **Estimated model/API spend:** $0 in paid LLM costs; public registry endpoint is treated as no-cost for this project. Internet, electricity and optional hosting are separate costs. Confirm current service terms and actual usage before declaring final costs.
- **Execution limits:** Collector has a short pause between pages. Avoid repeated unnecessary runs; cache profiles and stay under the hackathon's 2,000 outbound-request and 45-minute daily limits.

## Limitations and next improvements

1. The baseline's evidence links to the official entity record. It does not yet independently verify financial values against annual accounts or enrich from multiple sources.
2. Update detection compares current normalized fields with saved snapshots when a company is looked up again. It does not run a background scheduler.
3. For a stronger competition score, add more permitted sources only where each source is identity-matched and field-specific evidence is retained. Do not publish financial claims without a source and reporting period.
4. Before submission, improve retry/backoff handling, track total unique profiles explicitly, and run the evaluator-like tests on random organization numbers.
